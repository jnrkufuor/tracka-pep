# 09 · The app: one codebase for Android, iPhone and web

The app is written once in Flutter and built for all three. It trusts nothing it can't check, works offline, and every screen is tested at four phone widths with big text.

## The idea

The **app** is the part people touch. It's the **client**: it shows things and collects input, and asks the server for anything that must be shared, safe or heavy. The first rule: **the client is untrusted.** Anyone can modify an app or fake its requests, so every important check (who you are, what you may see) happens on the server.

## The usual ways to do it

| Approach | What it is | Examples | Trade-off |
| --- | --- | --- | --- |
| **Native** | A separate app per platform | Swift (iPhone), Kotlin (Android) | Best performance and feel; two codebases |
| **Cross-platform** | One codebase built for iPhone, Android and often web | **Flutter** (Dart), React Native (JavaScript) | One team, one codebase; occasional platform quirks |
| **Web app / PWA** | A website that behaves like an app | React, Vue, Flutter web | No store; weaker camera, storage and notification access |

What every app is made of: **widgets** (small reusable pieces combined into screens), **state** (the data the screen shows right now, and how changes redraw it), **navigation**, **networking** (with slow connections, retries and errors), and **local storage** (secrets go in **secure storage**: the iPhone Keychain or Android Keystore, never plain files).

Phone realities: slow and costly data, **permissions** (camera, notifications) that need the user's OK, **app store review**, and old versions that stay installed for months.

A **design system** keeps every screen looking like one product. Its smallest parts are **design tokens**: one decision with a name (`Tk.gold` instead of a colour code), named by *job* ("the warning colour"), not by look, so changing a token changes every screen at once.

## What we chose and why

- **Flutter**, because one small team can build Android, iPhone and the website from one codebase, and Flutter draws every pixel itself, so the app looks the same everywhere.
- **Provider for state**: one shared `AppState`, simple enough for our size.
- **Offline-first.** A clip is saved on the phone first and sent later (on Wi-Fi only if the player asked, when the connection returns, after the guardian says yes). Each clip carries an **idempotency key** so the server makes it once however often it arrives. The last good answer to each main screen is kept, so the app shows "You're offline. Showing what's saved." instead of an error.
- **Safety enforced by the server.** Under-18s need a guardian's yes before posting or being found; the app shows the steps, but the server enforces them.
- **Pitchside, a small social network built safe**: no messages at all, only a shirt name shown, block hides both players, three reports hide a clip until it's reviewed, and captions can't carry phone numbers, emails or links. Pep's notes are never shown on someone else's clip.
- **A design system with tokens by job**: your main colour (you), purple (Pep), gold (watch out), stone (calm extras). Dark theme only, and no red.
- **Accessibility built in**: text size, higher contrast, and reduce motion (changes happen instantly instead of animating).
- **No crash SDK in a children's app.** Crashes go to our own API (chapter 10).
- **Material as its own package** (`material_ui`), so the design library can update without waiting for a new Flutter.

## How it's set up

| Part | Where |
| --- | --- |
| Start-up and stages (starting → signed out → onboarding → ready) | `lib/main.dart` |
| Talking to the API (token, refresh on 401, streamed uploads, saved screens) | `lib/api/api_client.dart`, `lib/api/cache.dart` |
| App state | `lib/state/app_state.dart` |
| Upload queue | `lib/state/upload_queue.dart` |
| Screens (Home, Pitchside, +, Pep, Me) | `lib/screens/` |
| Tokens, motion, theme | `lib/theme/tokens.dart`, `motion.dart`, `theme.dart` |
| Shared components | `lib/widgets/ds.dart` |
| Icons (generated; don't hand-edit) | `scripts/build_brand.py` → `lib/widgets/*.g.dart` |
| Every screen at 360/390/412/430 px | `test/screens_test.dart` |

The `android/`, `ios/` and `web/` folders are generated by `tool/setup_platforms.sh`, so the repo holds only code we wrote.

## Workbook 09

**Try it**

1. With `pep serve` running, in `app/`: `./tool/setup_platforms.sh` then `flutter run -d chrome --dart-define=PEP_API_URL=http://localhost:8000`. Sign up and finish onboarding.
2. Log in as `demo@tracka.app` / `tracka-demo-123` (after `python scripts/seed_demo.py`) to see a full dashboard.
3. Turn off Wi-Fi mid-upload. What does the app do? Find the line in `UploadQueue` that sends it again when the network returns.
4. Turn on "Remove animations" on an Android phone and open the app. Find the line in `lib/theme/motion.dart` that makes changes instant.
5. Make a title in one screen much longer and run `flutter test test/screens_test.dart`. What does the failure say, and how would you fix the layout?

**Questions**

**1. Why check "is this my video?" on the server and not just in the app?**

*Answer:* Anyone can call the API directly with any video ID. Only the server can enforce it.

**2. Why Flutter instead of two native apps?**

*Answer:* One small team, one codebase for Android, iPhone and web, with the same look everywhere. The cost is occasional platform-specific work.

**3. Why are colours named by job ("watch out") instead of shade ("dark yellow")?**

*Answer:* Screens ask "what does this mean?". If warnings change colour, one token changes and every warning follows, and nothing that merely happened to be yellow changes by accident.

## More practice

Exercises added as features were built. Each one points at real code.

1. Install Flutter, then in `app/`: `./tool/setup_platforms.sh` and
   `flutter run -d chrome --dart-define=PEP_API_URL=http://localhost:8000`
   with `pep serve` running. Sign up and finish onboarding.
2. Run `python scripts/seed_demo.py` and log in as
   `demo@tracka.app` / `tracka-demo-123` to see a full dashboard.
3. Pick a different main colour in Settings and watch every button follow. Find
   where `context.accent` reads it in `lib/theme/tokens.dart`.
4. Turn off Wi-Fi mid-upload. What does the app do? What *should* it do?
   (Compare with the "Uploads" failsafe board on the design canvas.)
5. Plug in an Android phone and `flutter run`. Upload a real clip.
6. Turn on "Remove animations" (Android: Settings › Accessibility) and
   open the app. The splash and chips should change instantly. Find the
   line in `lib/theme/motion.dart` that makes that happen.
7. Sign up twice: once choosing "Get into an academy", once "Just looking
   around". Which steps did you skip the second time, and which line in
   `onboarding_screen.dart` (`flow`) decides it?
8. In `test/upload_queue_test.dart`, add a test: two clips on mobile data
   with Wi-Fi only on, then switch the fake network to Wi-Fi. Do both go?
   Which line in `UploadQueue` listens for the change?
9. Post a clip from one account and open the Feed from another. Then
   report it from three more accounts. In `tests/test_pitchside.py`, which
   assert proves the feed never carries Pep's notes?
10. `PepScreen.weekLine` turns your week into one sentence ("You have a
   match tomorrow. Keep today light."). Add the case of a match in 3 days to
   `test/pep_tab_test.dart`, then make it pass.
11. Pep's tour finds what to point at with GlobalKeys (`lib/widgets/tour.dart`).
   Hide "Tests and PBs" in Customise home, then run the tour from Settings ›
   Help. What does step 2 do when its card isn't there, and which line decides?
12. `test/screens_test.dart` builds every main screen at 360, 390, 412 and
   430 px, with XL text and with higher contrast, using a fake API. Make a
   title in one screen much longer and run it: what does the failure say,
   and how would you fix the layout (hint: `Expanded`, `Flexible`, `maxLines`)?
13. In `test/design_system_test.dart`, add `Color(0xFF7A2BFF)` (a purple)
   to the contrast test's list. Does it pass? Even if it did, why would
   Tracka still not offer it as a main colour?
14. Pep's moves live in `lib/widgets/pep.dart`, copied from the design's
   CSS keyframes (`pepBlink`: closed at 49% of a 5.5-second loop). Change
   the blink period to 2 seconds and watch Pep on Meet Pep. Why does a
   fast blink make him feel nervous rather than alive? Then turn on
   "Remove animations": what does Pep look like, and why is standing still
   at full size the right fallback?
