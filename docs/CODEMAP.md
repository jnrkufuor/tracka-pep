# Code map: where everything is

```
tracka-pep/
├── app/                          ★ THE PLAYER APP (Flutter: Android, iOS, web)
│   ├── lib/main.dart             start-up: starting → signed out → onboarding → ready
│   ├── lib/config.dart           PEP_API_URL (and CI-only screenshot mode)
│   ├── lib/api/                  api_client.dart (tokens, refresh, streamed uploads), models.dart (JSON types)
│   ├── lib/state/app_state.dart  the one ChangeNotifier: user, profile, videos, coach; polls while processing
│   ├── lib/screens/              splash, auth, onboarding, shell (tabs: Home, Pitchside, +, Pep, Me), training
│   │                             (week, session, done, health, your football),
│   │                             home, pitchside, videos, upload, video, pep, profile (+ edit, settings)
│   ├── lib/theme/tokens.dart     design tokens: colours by job (Tk), MainColour, rating Band/Confidence/Trend
│   ├── lib/theme/motion.dart     durations, easing, reduce motion
│   ├── lib/theme/theme.dart      Material theme built from the tokens + the player's main colour
│   ├── lib/widgets/ds.dart       design-system components (chips, band pill, notes, sheets, toasts, failsafes)
│   ├── lib/widgets/              other shared widgets; line_icons.g.dart and loopy_icons.g.dart are GENERATED by build_brand.py
│   ├── test/                     flutter tests
│   └── tool/setup_platforms.sh   creates android/ ios/ web/ (not in git) and patches permissions + icons
├── pep/                          the Python package (everything that runs on servers)
│   ├── __init__.py               MODEL_VERSION: bump when measurements or scoring change
│   ├── config.py                 every setting (env vars), with defaults and explanations
│   ├── contracts.py              the Tracka <-> Pep contract as pydantic models (camelCase on the wire)
│   ├── pipeline.py               ★ START HERE: the whole analysis, stage by stage, timed
│   ├── cli.py                    `pep analyse | worker | drain | serve`
│   ├── log.py                    structured logging (JSON in production)
│   ├── db.py                     tables + the job queue (SKIP LOCKED, leases, backoff, callbacks)
│   ├── worker.py                 claim → download → analyse → save → callback; heartbeat; SIGTERM
│   ├── callbacks.py              signed webhooks back to Tracka (HMAC-SHA256), with retries
│   ├── storage.py                local disk or S3/R2; presigned URLs
│   ├── evaluation.py             agreement with scouts: MAE, bias, Spearman
│   ├── overlay.py                debug video: box, skeleton, trail, live speed
│   ├── video/frames.py           probe + sample frames (a generator)
│   ├── vision/
│   │   ├── types.py              Box, Person, FrameObs, COCO keypoint indices
│   │   ├── perception.py         YOLO26 pose (+ ByteTrack) and ball detection (+ zoomed second look)
│   │   ├── camera.py             camera-motion compensation (corners, optical flow, RANSAC)
│   │   ├── target.py             pick the player, stitch broken tracks, follow them
│   │   └── calibration.py        pixels → metres (homography for drills, pinhole body ruler otherwise)
│   ├── metrics/
│   │   ├── kinematics.py         Kalman + RTS smoother; speed, accel, distance, sprints, turns
│   │   ├── ball.py               touches, ball at feet, close control, heavy touches
│   │   ├── technique.py          joint angles from pose: ready stance, sprint lean, scanning
│   │   └── goalkeeping.py        dives, dive speed, set position
│   ├── drills/runner.py          30 m sprint, 5-10-5, keepy-ups, wall passes
│   ├── scoring/
│   │   ├── norms.py              z-scores, percentiles, age bands
│   │   ├── skills.py             ★ the rulebook: measurements → skills, explanations, drills, confidence
│   │   ├── roles.py              role fit, overall score, overall confidence
│   │   └── learned.py            the trained scorer: FEATURES (predictors) + prediction
│   ├── coach/
│   │   ├── llm.py                Gemini: upload video, structured JSON notes, guardrails
│   │   └── merge.py              combine measurements and AI notes; rule-written fallback summary
│   ├── players/                  ★ the app's API (/v1)
│   │   ├── routes.py             auth, /me (profile + settings), /meta, /videos, /coach, /opportunities
│   │   ├── auth.py               scrypt password hashing, JWT access + refresh tokens (rotation, reuse detection)
│   │   ├── store.py              tables: users, profiles, videos, sessions
│   │   ├── coach.py              the player's dashboard: overall score, trend, focus skill, drill, roles
│   │   ├── training.py           the week (computed), Pep sessions, events, health: tables + rules
│   │   ├── training_routes.py    /v1/week, /v1/sessions, /v1/events, /v1/health
│   │   ├── guardian.py           guardian approval: link code, texted one-time code, yes/no, revoke
│   │   ├── guardian_routes.py    /v1/guardian (player), /v1/g/{code} (guardian), /v1/sms/inbound
│   │   ├── sms.py                texts: PLACEHOLDER outbox until an SMS provider is chosen
│   │   ├── pages.py              web pages without the app: /g/{code} (guardian), /legal/*
│   │   ├── notifications.py      the bell: events (review ready, respect, guardian) + sweep (sessions, games); push placeholder
│   │   ├── pitchside.py          Feed, posts, respect, follow, block, report, search, challenges, pitches
│   │   ├── card.py               player card + share link (/v1/card, /v1/c/{token}); only safe fields
│   │   ├── review.py             Pep's review of a clip: headline, moments, tips + kit-aware drills (/v1/tips)
│   │   ├── details.py            onboarding v2 details (shirt, town, level, goal, style, weaker foot, guardian phone)
│   │   └── skill_areas.py        Me tab: bands, measured averages, confidence, trend per skill area
│   ├── api/app.py                FastAPI app: mounts /v1, /analyses (tracka-api contract), /lab/* (staff console),
│   │                             /files (signed local links), /healthz /readyz /metrics
│   └── data/
│       ├── norms.json            reference values per age band (starter priors: replace with real data)
│       ├── roles.json            scout roles and skill weights (football opinion: review with coaches)
│       ├── drills.json           drill definitions and cone layouts
│       ├── skill_areas.json      skill areas by group, their measurements, key areas per position
│       └── training.json         Pep's training library: warm-up, drills per skill area, tests, light day
├── web/                          Pep Lab: a staff console (plain HTML/CSS/JS served by the API)
│   ├── index.html, app.css, app.js
│   └── assets/                   fonts, brand/ (logo, app icon), icons/ (+ icons/line/) + icons.js (generated)
├── training/                     offline ML work
│   ├── train_scorer.py           learn scout ratings (gradient boosting, GroupKFold)
│   ├── finetune_detector.py      fine-tune YOLO26 on football frames
│   ├── build_norms.py            norms from Tracka's own players (median/MAD)
│   ├── evaluate.py               benchmark accuracy report + CI gate
│   └── make_benchmark.py         synthetic clips with known speeds
├── scripts/
│   ├── make_test_clip.py         a clip with a known top speed (25.2 km/h)
│   ├── seed_demo.py              a demo player with analysed clips (demo@tracka.app / tracka-demo-123)
│   └── build_brand.py            generates logo, app icon and icon sets for web AND app (single source of truth)
├── deploy/modal_app.py           GPU workers on Modal (drain + kick)
├── tests/                        pytest: contracts, kinematics, geometry, drills, scoring, queue, API, training
├── docs/handbook/                the learning handbook (00 → 12): concept first, then Tracka as the example, then a workbook
├── Dockerfile                    API image (Render builds this)
├── Dockerfile.worker             worker image (PyTorch, YOLO, ffmpeg)
├── docker-compose.yml            Postgres + MinIO + API + worker, locally
├── render.yaml                   Render Blueprint (API, Postgres, optional CPU worker), Frankfurt
├── .github/workflows/            ci.yml, app.yml (Flutter: test, web, Android), deploy.yml,
│                                 evaluate.yml, screenshots.yml; dependabot.yml
└── pyproject.toml                dependencies (extras: vision, coach, train, dev) + tool settings
```

## "I want to…"

| …change | go to |
|---|---|
| a screen in the app | `app/lib/screens/<name>_screen.dart` |
| guardian approval | `pep/players/guardian.py`, `app/lib/screens/guardian_screens.dart`, page in `pep/players/pages.py` |
| Pep tab, focus and tests | `app/lib/screens/pep_screen.dart`, `GET /v1/focus` in `pep/players/training_routes.py` |
| notifications | `pep/players/notifications.py`, `app/lib/screens/notifications_screen.dart` |
| Pitchside (feed, challenges, near you) | `pep/players/pitchside.py`, `pep/data/challenges.json`, `app/lib/screens/pitchside_screen.dart`, `feed_screens.dart` |
| upload queue, offline | `app/lib/state/upload_queue.dart`, `app/lib/api/cache.dart`, `app/lib/screens/uploads_screen.dart`, `upload_keys` in `pep/players/store.py` |
| player card, share link, privacy | `pep/players/card.py`, `app/lib/screens/card_screens.dart`, page `/c/{token}` in `pages.py` |
| Pep's reviews and tips | `pep/players/review.py`, `app/lib/screens/review_screens.dart` |
| onboarding steps (Meet Pep → 5 steps → All set) | `app/lib/screens/onboarding_screen.dart`, `pep/players/details.py` |
| what the app gets from the API | `pep/players/routes.py` (and `app/lib/api/models.dart`) |
| the player's dashboard numbers | `pep/players/coach.py` |
| how Pep plans the week, or a training drill | `pep/players/training.py`, `pep/data/training.json` |
| the Me tab's skill areas, bands, key areas per position | `pep/players/skill_areas.py`, `pep/data/skill_areas.json` |
| sign-up, login, tokens | `pep/players/auth.py` |
| app colours, fonts, motion | `app/lib/theme/tokens.dart`, `motion.dart` (theme.dart builds from them) |
| a shared app component | `app/lib/widgets/ds.dart` |
| how a score is explained, or the drill suggested | `pep/scoring/skills.py` |
| what a role values | `pep/data/roles.json` |
| what "good for a U15" means | `pep/data/norms.json` (or `training/build_norms.py`) |
| a speed or touch definition | `pep/metrics/*.py` (then bump `MODEL_VERSION`) |
| the detector or pose model | `PEP_DETECTOR_MODEL` / `PEP_POSE_MODEL`, or `vision/perception.py` |
| what the AI coach is told | `pep/coach/llm.py` (`SYSTEM`, `build_prompt`) |
| what Tracka receives | `pep/contracts.py` (and tracka-api's `coachResultSchema`) |
| a Lab (staff console) page | `web/app.js` (one function per page) |
| colours, fonts, radii | `web/app.css` `:root` |
| the logo or icons | `scripts/build_brand.py`, then run it |
| retries, leases, timeouts | `pep/config.py` (env vars) |
